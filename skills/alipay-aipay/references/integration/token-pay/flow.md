# AI连续订阅（Token Pay）· 周期订阅开发接入

交付时按实际工程改动和验证结果说明接入进展，并注明验证是在本地模拟环境还是产品允许的非生产环境。

沙箱基础配置共用[公共沙箱模块](../sandbox/sandbox-setup-guide.md)：先 ensure 完整获取或复用项目根 `.alipay-sandbox.json`，再进入本产品的调用登记、通知和订阅联调。工程语言不影响获取配置。仅替换原浏览器获取基础凭据的步骤，不调用 `sandbox summary`，不接入收单的摘要、提醒和待配置消息，不新增 APPID、PID、买家资料或配置路径的对客展示；任务进度及阻塞仍按本产品流程反馈。

本文只承接周期订阅工程。明确点名特定接入身份、受限接口或生产测试客户说明时才查[专项适用条件](access-modes.md)；普通开发不加载，不把其他专题列为默认方案。

## 适用范围

仅在商家明确希望推进周期订阅首次接入、现有工程实施、继续未完成接入、最小闭环或生产上线验收时使用本指南。

以下请求不使用完整执行流程：

- 只询问某个产品、API、字段、状态或通知语义。
- 只要求一段局部代码示例。
- 已经给出具体错误或失败现象，只需要定点排障。

定点排障只有在证据确认故障来自开通、授权、应用或回调准备缺口时，才回写对应准备度门禁；不要先让用户完成整套检查。

只问商家申请和授权时读取[订阅商家办理指引](../../onboarding/token-pay/guidance.md)。进入工程后先区分商户开通与会员支付签约，再按当前任务直接读取资料：

| 目标 | 直接资料 |
|---|---|
| 创建客户、价格、订阅，或排查错误字段 | [快速接入](quickstart.md)、[公开接口](api-complete.md)、[字段与状态约束](subscription-contracts.md) |
| 选择 SDK、搭建 Demo 或改造现有工程 | [按语言和交付目标选择](dev-options.md)。已有 Java 或 Go 工程也可直读 [Java 示例](code-example-java.md)或 [Go 示例](code-example-go.md) |
| 会员权益、续费、取消或退款 | [通知处理](notification-guide.md)、[公开契约](subscription-contracts.md) |
| 团队席位、试用或未来生效 | [团队席位](seats.md)、[商户准入](merchant-default-controls.md)、[营销能力](marketing-tools.md)、[未来生效](scheduled-effective.md) |
| 托管页与价格表 | [低代码工程](low-code-integration.md)、[价格表下单](price-table-order.md) |
| 沙箱工程或已有堵点 | [沙箱交付](sandbox/sandbox-delivery.md)、[排障](troubleshooting.md) |

本 Skill 的联调执行仅用订阅沙箱或本地模拟；沙箱使用同一环境的凭据、资源、网关与测试时钟。生产配置说明、代码实现和已有脱敏证据可用于上线准备；本包不在生产网关运行验证。缺少本包执行能力的申请只给当前官方入口。

## 默认黄金路径

用户没有提出特殊能力时，以最高频的最小方案推进：

```text
普通商户
→ 支付宝托管扣款 SUBSCRIBE_DEDUCT
→ IMMEDIATE_EFFECTIVE 立即生效
→ 单商品、单价格、单订阅项
→ 无试用、优惠券、未来生效或席位能力
→ 目标语言存在官方 SDK 时优先使用官方 SDK
→ 跑通创建、支付签约、异步通知、主动查询和权益处理闭环
```

未来生效、试用优惠、团体席位、立即取消退款等，仅在用户明确提出时读取对应参考并切换分支。低频能力必须保持描述、代码和公开契约一致，但不应增加默认接入路径的认知负担。

## 接入阶段

按本轮目标选择开发、联调或上线准备，不以是否持有正式密钥决定执行环境：

| 商户当前情况 | 下一步 |
|---|---|
| 已申请并拿到正式应用及配套密钥 | 商家可在核对权限、授权与通知配置后按[生产验收指引](production-environment.md)直接验证。本 Skill 核对商家已有脱敏证据，需要代为运行开发验证时使用独立沙箱或本地模拟 |
| 尚未拿到正式密钥，包括申请中 | 主动推荐先做沙箱验证，正式申请可同时继续，不因等待正式密钥阻塞开发与模拟联调 |
| 已明确选择沙箱或生产 | 沙箱按对应流程执行；只要求生产时检查配置和已有脱敏证据，并列出须由商家按正式流程完成的事项，不替其调用生产网关，也不擅自改测沙箱 |
| 是否已有正式密钥不明 | 开发和沙箱联调无需追问正式密钥；仅当上线准备取决于此项时才核实是否已配置，不索取私钥正文 |

选择沙箱的工程实施任务按[沙箱自动接入交付](sandbox/sandbox-delivery.md)检查工具并执行：尽量只交接必要登录授权，随后自动配置沙箱、改造商家工程，验证首次购买、通知与权益、一次续费及期末取消。具体页面和接口按[沙箱接入指南](sandbox/sandbox-integration.md)。用户限定范围时尊重其范围；无需安装 App 或日常手填 PID。下表的生产产品开通、生产授权与经营门禁留到转生产时单独核验。持有正式密钥不证明权限、通知或交易结果已验证。

| 阶段 | 目标 | 进入下一阶段的证据 |
|---|---|---|
| 1. 产品适配 | 确认商家业务适合周期订阅，并了解准入、费率和经营要求 | 商家目标明确，账号与经营条件不存在已知阻塞 |
| 2. 平台准备 | 本地模拟使用测试配置；独立订阅沙箱准备沙箱应用和沙箱凭据；转入正式调用时核对正式产品开通、调用应用、支付能力和[新商户代调用授权](../../onboarding/token-pay/guidance.md#新商户代调用授权必需) | 只按当前环境核对所需配置、控制台结果或权限回执 |
| 3. 技术准备 | 配置目标环境的调用身份、密钥或证书、网关和公网通知地址 | 同一环境的配置检查、连通性或验签验证结果 |
| 4. 工程实施 | 在现有工程中实现最小调用链、通知、查询、幂等和权益处理 | 真实构建和相关自动化测试通过 |
| 5. 联调闭环 | 使用受控测试数据跑通创建、支付签约、通知、查询和权益结果 | 可关联的 API、通知、查询与业务状态证据 |
| 6. 上线验收 | 检查可靠性、安全、监控、投诉处置和发布准备 | 所有阻塞门禁已验证，遗留风险已明确接受或解决 |

阶段用于识别下一步，不要求用户从第一阶段重新开始。已有证据可以直接复用；用户已经完成的阶段只需核验，不重复讲解或执行。

## 执行循环

对接入推进任务持续执行以下循环：

1. **识别当前阶段**：结合用户描述、工作区、配置、构建结果和外部证据，找到最靠前的未完成门禁。
2. **核验证据**：区分用户口述、静态配置、构建测试、真实接口响应和完整交易闭环，不把它们视为同等级证据。
3. **完成当前动作**：能在用户授权范围内检查或修改的直接完成；能运行的构建、测试和静态检查实际运行。
4. **验证结果**：以可观察结果判断本阶段是否完成。失败时保留失败事实和最小诊断信息，不用示例输出代替真实结果。
5. **更新准备度**：只更新本次获得新证据的门禁，保留其他门禁原状态。
6. **推进下一步**：能执行则继续到下一验收点，不在每步完成后等待用户再说“继续”；只有确须商家完成的动作才交接，说明操作、预期结果和恢复位置。登录完成后优先直接读取验证结果，不让商家转述可由工具获取的信息。

## 不同接入任务的处理方式

### 首次接入或“怎么接”

- 先确认业务目标是否属于周期订阅，再区分开发、沙箱联调或上线准备，检查该任务最靠前的准备项。
- 不一次性询问全部信息；只问会改变当前下一步的必要信息。
- 前置条件未完成时给出具体商家动作；尚无正式密钥时优先推荐沙箱，代码实现和可离线验证的工作可继续推进。

### 在现有工程中实施

- 优先检查工作区中的语言、框架、依赖、配置方式和已有支付代码，不重复询问可直接发现的信息。
- 在现有架构内完成最小闭环，避免为了接入订阅重构无关代码。
- 修改后运行真实构建和相关测试；未运行或失败时不得声称工程接入完成。
- 平台准备尚未验证不妨碍完成可离线验证的代码，但要把外部依赖保留为阻塞项。

### 继续未完成接入

- 复用用户提供的历史结果和已有准备度，不从产品介绍重新开始。
- 先确认上一次阻塞项是否已有新证据，再继续后续动作。

### 最小闭环联调

- 联调前确认测试范围、金额、测试客户和数据处置方案；禁止由 Agent 自行发起生产真实交易。
- 页面跳转或同步响应不能单独证明支付、签约或权益成功；按公开契约收集通知、查询和商户业务状态证据。
- 沙箱分别验证接口调用、工作台模拟确认、商家通知处理和权益查询；本地演示、发送记录或沙箱闭环均不能代替生产验收。

### 上线验收

- 使用 [订阅上线条件](../../onboarding/token-pay/guidance.md) 检查全部门禁。
- 明确区分已验证、仅口述、尚未检查和被阻塞的项目；存在阻塞项时不得给出“已可上线”的结论。

## 信息收集与停止条件

- 信息足够时直接执行，不为了填满模板而追问。
- 缺少的信息如果不会改变当前动作，可以先采用安全默认值并明确假设。
- 身份验证、必要授权确认、审核或生产真实用户支付需要商家完成时，只暂停依赖该动作的部分，给出最小交接说明；沙箱配置、模拟支付和测试时钟先检查可用工具，在已授权范围内自动执行，不因涉及平台页面就停止。
- 不要求用户在对话中粘贴私钥、证书正文或完整敏感报文；使用安全配置注入和脱敏证据。
- 用户只要求回答或诊断时，在当前问题解决后结束，不自动扩展为完整接入项目。

## 接入推进输出

根据实际情况选择必要项，不机械输出空标题：

- **当前阶段**：商家正在完成的接入阶段。
- **已验证**：证据支持的完成项及证据类型。
- **阻塞项**：阻止当前阶段完成的事实。
- **本次完成**：已经执行并验证的工作。
- **商家待办**：只能由商家完成的控制台、审核、授权或真实用户动作。
- **下一验收点**：下一步成功时应看到的具体结果，以及需要继续提供的证据。

直接问答和定点排障不使用这套完整输出结构。
