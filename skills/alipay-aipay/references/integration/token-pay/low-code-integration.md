# 低代码接入详细指南

商品配置先按[商户默认管控规则](merchant-default-controls.md)核对价格和周期。本文年付示例超出默认最长 3 个月／93 天的周期，仅用于说明配置形式；未确认商户实际能力前不得作为默认接入方案。试用同样默认不可用。

> 文档来源：https://opendocs.alipay.com/ai-solution/0jg567.md
> 更新时间：2026-06-02

---

## 一、产品特色

支付宝为订阅业务提供的仅需通过极少研发、即可高效对接支付的解决方案，通过**免研的商品价格表与收银台**，帮助商户快速实现业务的商业化。

### 核心优势

- ✅ **无需开发商品列表和收银台页面**
- ✅ **无需处理复杂的支付流程**
- ✅ **仅需在支付宝后台进行简单配置**
- ✅ **可视化配置，实时预览**
- ✅ **快速上线，验证商业模式**

### 适用场景

- 快速验证商业模式
- 商品种类较少、价格结构简单的业务
- 研发资源有限的团队
- 不需要高度定制化的场景

### 用户体验流程

```
商家调用接口并打开 checkout_url → 用户在托管页面选择价格 → 完成支付与订阅签约 → 回跳商家页面
```

---

## 二、低代码接入流程

### 流程图

```text
商家平台创建商品和价格
  → 创建价格表、配置回跳地址
  → 取得 page_code
  → 调用 alipay.trade.commercial.order.create
  → 原样、立即打开返回的 checkout_url
  → 用户在托管页面选价并支付签约
  → 回跳商家页面，通知与查询确认终态
```

---

## 三、详细步骤

### 3.1 创建商品

**步骤**：
1. 登录 [支付宝工作台](https://open.alipay.com/)
2. 在左侧"解决方案"菜单栏找到"支付 SAAS 工作台"
3. 点击进入管理页面
4. 在"商品管理"页面，点击"新建商品"按钮
5. 进入商品配置页面，创建对应的商品和价格信息

**商品配置项**：
- 商品名称（签约页面展示，务必准确）
- 商品描述
- 商品图片（最多5张）
- 营销信息（最多5个）
- 单位别名（团体订阅必填，如"席位"）
- 商品详情页跳转地址

---

### 3.2 配置价格表

**步骤**：
1. 进入[商家平台价格表管理](https://b.alipay.com/page/checkout-management/price-management/list)
2. 点击「新建价格表」，进入配置页面
3. 在页面左侧填写配置项，并在右侧实时预览效果
4. 关联要展示的商品和价格，保存价格表
5. 从价格表详情中取得页面编码 `page_code`；后续创建商业订单传这个值，不传价格表名称，也不在此时指定某个 `price_id`

**价格表配置项**：
- 价格表名称
- 选择商品（关联已创建的商品）
- 设置价格方案：
  - 月付价格
  - 季付价格
  - 年付价格
  - 其他自定义周期
- 价格展示样式
- 营销文案（如"首月8折"、"限时优惠"）

**实时预览**：
- 配置右侧实时显示最终效果
- 支持预览移动端和PC端样式
- 支持分享预览链接给团队

---

### 3.3 配置收银台

**步骤**：
1. 进入收银台配置页面
2. 页面左侧为待填写配置项
3. 页面右侧支持按照配置项实时预览生成效果

**收银台配置项**：
- 收银台标题
- 收银台logo
- 支付方式说明
- 服务协议链接
- 隐私政策链接
- 客服联系方式
- 自定义样式（颜色、字体等）

**支付后跳转**：
- 支付成功页跳转地址
- 支付失败页跳转地址
- 支付取消页跳转地址

这些地址应在把价格表接入生产流量前预先配置。`redirect_url` 是商业订单创建接口的可选兼容字段；如果调用方同时传入，当前服务会保存该值并提供给 Hosted 页面，建议与平台成功回跳配置保持一致。

---

### 3.4 管理价格表

**筛选查询**：
- 价格表名称
- 页面编码 `page_code`
- 包含的产品名称
- 使用状态

**支持的操作**：

| 操作 | 说明 |
|-----|------|
| 查看价格表 | 查看价格表 ID、页面编码 `page_code`、配置和预览 |
| 修改价格表 | 编辑价格表配置 |
| 删除价格表 | 删除价格表和收银台 |

---

### 3.5 通过 `page_code` 获取 Hosted 页面

生产环境不要把商家平台预览链接直接交给用户，也不要手工拼接收银台地址。每次都先创建商业订单，再原样使用本次响应中的 `checkout_url`。

**接口**：`alipay.trade.commercial.order.create`

**作用**：
- 创建 `SUBSCRIPTION/PRE_CREATED` 价格表预订单
- 返回带本次订单上下文的 `checkout_url`
- 让用户在支付宝托管页面选择价格并完成支付订阅

`page_code` 路径只支持默认的 `HOSTED` 模式。不要同时传 `price_id`，也不要用 `order_type` 选择订阅；完整字段与响应契约见[商业订单创建接口](price-table-order.md)。

**请求示例**：
```json
{
  "page_code": "价格表页面编码",
  "customer_id": "客户ID",
  "ui_mode": "HOSTED"
}
```

回跳地址在商家平台中预先配置。若接入方还传 `redirect_url`，请使用与平台成功回跳配置一致的地址。

**响应示例**：
```json
{
  "alipay_trade_commercial_order_create_response": {
    "code": "10000",
    "msg": "Success",
    "checkout_url": "RETURNED_CHECKOUT_URL",
    "expire_time": "RETURNED_EXPIRE_TIME",
    "order_no": "YOUR_ORDER_NO",
    "order_type": "SUBSCRIPTION",
    "status": "PRE_CREATED"
  },
  "sign": "RETURNED_SIGN"
}
```

响应验签成功后：

1. 立即保存 `order_no`。
2. 直接跳转或打开原样返回的 `checkout_url`，不要自行补参数、替换域名或长期缓存后再使用。
3. 不要把 `PRE_CREATED` 当作订阅或支付成功；这时用户尚未选价。

---

### 3.6 用户选价、支付与回跳

完整运行流程：

1. 商家为当前用户打开创建接口返回的 `checkout_url`。
2. 托管页面根据 `page_code` 展示价格表，用户选择对应价格。
3. 选价后预订单从 `PRE_CREATED` 推进为真实待支付订单，用户继续完成支付与订阅签约。
4. 页面操作完成后回到商家平台预先配置的回跳页面；若创建请求同时传了 `redirect_url`，其值应与平台配置保持一致。

**支付成功后**：
1. 通过正式通知能力和订单/订阅查询确认结果；不要依赖创建请求中的 `hook_url`
2. 浏览器回跳只负责页面导航，回跳本身不能作为支付或签约成功依据

## 四、低代码接入与API接入对比

### 对比表格

| 对比项 | 低代码接入 | API 接入 |
|-------|----------|---------|
| **开发成本** | 低，仅需后台配置 | 高，需开发商品列表和收银台 |
| **上线时间** | 1-2天 | 1-2周 |
| **自定义程度** | 有限，受限于模板 | 完全自定义 |
| **页面样式** | 支付宝标准模板 | 完全自定义 |
| **支付流程** | 支付宝处理 | 商户自己处理 |
| **适用场景** | 快速验证、商品少、价格简单 | 深度定制、商品多、价格复杂 |
| **研发资源** | 需求低 | 需求高 |
| **品牌一致性** | 有限 | 完全一致 |

### 选择建议

**选择低代码接入**：
- ✅ 快速验证商业模式
- ✅ 商品种类少于10个
- ✅ 价格结构简单（月付/年付）
- ✅ 研发团队少于3人
- ✅ 对品牌一致性要求不高

**选择API接入**：
- ✅ 需要深度定制化页面
- ✅ 商品种类多、价格结构复杂
- ✅ 对品牌一致性要求高
- ✅ 有充足研发资源
- ✅ 需要特殊的业务逻辑

## 五、低代码接入最佳实践

### 5.1 商品配置建议

**商品名称**：
- ✅ "AI会员专业版-月付"
- ✅ "企业协作工具-年度订阅"
- ⚠️ 不建议：过长或过于复杂的名称

**商品描述**：
- ✅ 简洁明了，突出核心价值
- ✅ 列出主要功能点
- ⚠️ 不建议：冗长的描述

**商品图片**：
- ✅ 高清、美观的产品图
- ✅ 展示产品核心功能
- ⚠️ 不建议：模糊或无关的图片

### 5.2 价格表配置建议

**价格方案设计**：
- 月付：原价
- 季付：9折优惠
- 年付：8折优惠

**营销文案**：
- ✅ "限时优惠，年付立省20%"
- ✅ "首月5折，满意再续费"
- ⚠️ 不建议：过于夸张或不实的文案

### 5.3 收银台配置建议

**必填项**：
- 服务协议链接
- 隐私政策链接
- 客服联系方式

**样式建议**：
- 颜色与品牌色调一致
- 字体清晰易读
- 布局简洁明了

### 5.4 回跳与结果处理

**支付成功后**：
1. Hosted 页面按配置回跳商家页面；此动作只用于页面导航
2. 商家通过正式订阅通知接收状态变化，并验证通知签名、按业务主键幂等处理
3. 使用订单/订阅查询补偿确认最终状态后，再更新用户订阅状态和开通权益
4. 不要把 `redirect_url` 回跳或创建请求中的 `hook_url` 当作支付成功通知

**支付失败后**：
1. 记录支付失败原因
2. 引导用户重新支付
3. 提供客服联系方式

## 六、常见问题

**Q1: 低代码接入支持哪些支付方式？**
A: 支持支付宝余额、银行卡、信用卡等支付宝支持的支付方式

**Q2: 收银台页面可以自定义吗？**
A: 可以自定义logo、颜色、字体等，但无法修改整体布局

**Q3: 如何处理支付回调？**
A: 浏览器回跳与异步通知是两件事。回跳只负责页面导航；订阅结果通过正式订阅通知接收并验签，同时使用订单/订阅查询做补偿确认。

**Q4: 价格表可以随时修改吗？**
A: 可以修改，但已购买的订阅不受影响，仅影响新购买的用户

**Q5: 低代码接入支持团体订阅吗？**
A: 支持，需要在商品创建时填写 `unit_label`（如"席位"）

**Q6: 如何实现试用期？**
A: 低代码接入目前不支持试用期，需使用API接入

**Q7: 如何使用优惠券？**
A: 低代码接入目前不支持优惠券，需使用API接入

**Q8: 如何查看订单和订阅数据？**
A: 登录支付宝商家后台，在"订单管理"和"订阅管理"中查看

## 七、错误处理

| 错误 | 原因 | 解决方案 |
|-----|------|---------|
| 价格表未找到 | page_code 错误 | 检查价格表页面编码是否正确 |
| 商品已下架 | 商品状态异常 | 登录商家后台检查商品状态 |
| 订单创建失败 | 参数格式错误 | 检查请求参数格式 |
| 签名验证失败 | 签名算法错误 | 检查签名算法和密钥 |
