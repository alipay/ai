# 商户默认管控规则

规则基线：2026-09-03；同步日期：2026-09-17。本页的默认能力、商品定价、扣款周期和首次购买规则用于周期订阅，不作为 AI连续订阅（Token Pay）其他能力的通用限制。未取得商户实际能力已调整的证据时，按以下默认值回答；接口支持某个参数，不代表商户默认可用。

## 默认规则与场景

| 管控项目 | 默认规则 | 场景示例与适用范围 |
|---|---|---|
| 试用期能力 | 默认不支持试用期 | 按月续费会员先提供 7 天试用，默认不可用。免费、低价试用示例均以实际已获得对应准入为前提 |
| 倍数管控 | 首次订阅购买，后续周期实际扣款金额不得超过首笔实际支付金额的 3 倍 | 首月 10 元、后续每月 50 元不符合；首月 10 元、后续每月 30 元符合该项规则。试用期和订阅升级不受 3 倍管控；普通首期优惠不能被当成试用期来排除此规则 |
| 绝对低价管控 | 首次支付金额不能低于 1.00 元（100 分） | 首期 0.10 元不符合。已获准的零元创建按零元准入处理；试用期不受 3 倍管控，不代表正金额试用自动豁免 1 元下限 |
| 商品价格管控 | 单笔支付价格最高 500 元（50000 分） | 会员商品单价 800 元不符合；500 元符合该项规则。不要将此金额上限泛化成企业支付等其他产品的全局限制 |
| 商品周期最短管控 | 周期不能小于 7 天 | 每 5 天扣款一次不符合；每 7 天符合该项规则 |
| 商品周期最长管控 | 周期不能大于 3 个月／93 天 | 每年扣款一次不符合默认规则；按月配置最多 3 个月，按天配置最多 93 天。不要把日历月固定换算成 31 天 |
| 用户数管控 | 商家通过周期订阅使用已签约的「商家扣款」产品时，每个商家默认累计可新签 5000 名用户 | 达到商家当前额度后，新增签约会被拦截。已有订阅仍可查询、续费或变更。统计按累计新签人数计算，不能假设取消订阅会释放名额。团队套餐的席位数单独计算。 |

## 回答和接入时的判断

- 普通正金额首次订阅购买同时满足 1 元下限和 3 倍规则：`首笔实际支付金额 x 3 >= 后续周期扣款金额`，最低金额为 `max(1.00 元, 后续周期扣款金额 / 3 后向上取分)`。例如后续每月 100 元，首笔最低 33.34 元。满足某一项不代表所有规则均通过。
- 试用期默认不可用；已获准时按免费或低价试用对应的准入和参数契约执行。试用期不受 3 倍管控，不应把“5 元试用、后续每月 38 元”仅因比例而判为违规，也不能据此认定商户已经获得试用能力。
- 1 元和 3 倍规则针对订阅创建，不外推到升级或扩容的本次变更金额。其金额链路见 [完整 API 参考](api-complete.md)。不受倍数限制不等于商品价格、周期等其他规则自动豁免。
- `recurring.interval=DAY` 时默认 `interval_count` 为 7–93；`MONTH` 时为 1–3。接口的 `DAY` / `MONTH` 枚举与商户可用周期是两层约束，不能通过 `MONTH + 12` 绕过最长周期。计费周期限制不是 `trial_period_days` 的取值范围。
- 原规则以“单笔支付价格”描述 500 元上限，并用商品单价举例；没有单独解释多席位合计与单价的校验层级。涉及 `quantity` 时同时列出单价和整单金额，核对实际接口结果，不宣称每席不超 500 元便可无限放大整单金额。
- 根据脱敏后的实际 `sub_code` / `sub_msg` 判断拦截，不编造固定错误码，不通过换客户、换价格、拆分或重复请求绕过规则。商家需要提高新签额度时，见[累计新签人数达到上限时的处理](troubleshooting.md#累计新签人数上限)。
- 本文不包含逐项特殊申请资格，不根据默认规则推断“可申请”或“不可申请”，不承诺申请结果或时效。商户个别能力是否已调整，以可核验的准入结果为准。
