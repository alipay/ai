# 服务商代开发模式接入指南

仅在用户明确询问 ISV、第三方应用代调用或服务商通知时看本文件。新商户的代调用授权准备不代表其选择服务商模式。仅看到接口示例中的 `app_auth_token`，不能据此判断商户已采用服务商模式。[开放平台订阅接入准备](https://opendocs.alipay.com/solution/repo-046zj4.md)目前写明暂不支持服务商代开发。存量商户明确询问已有第三方授权时，可用本页核对签约范围、调用身份和通知。新申请的可用范围需由产品对接人核实。企业支付 B2B 仅支持自有应用。

> 适用对象：希望由服务商完成支付宝订阅技术接入的商户，以及已获得商户授权的服务商。
>
> 本文只描述商家和服务商可配置、可调用、可接收的公开契约。控制台入口、授权范围和准入结果以开放平台实际展示及正式接入资料为准。

## 一、模式说明

服务商代开发模式是指：商户在支付宝开放平台将所需业务权限授权给服务商的第三方应用，由服务商负责接口开发、运行维护和消息处理，并代表该商户调用支付宝订阅接口。

这套模式下：

- 商户仍是商品、客户、订阅和交易的业务归属方，资金结算以商户签约和结算配置为准。
- 服务商使用自己的第三方应用和应用私钥完成签名；证书模式还需配置与该应用匹配的证书信息。
- `app_auth_token` 证明“当前服务商应用已获得当前商户的代调用授权”。
- 商户不需要把自己的应用私钥交给服务商。
- 服务商只能在授权范围内操作，并必须按商户隔离令牌、资源和通知。

一句话理解：**商户授权，服务商代开发和代调用，支付宝按被授权商户归属处理业务。**

## 二、概念区分

| 维度 | 可选方式 | 决定什么 |
|---|---|---|
| 技术接入方 | 商家自研 / 服务商代开发 | 谁持有调用应用的密钥、谁调用接口和处理通知 |
| 周期扣款方 | 支付宝托管 / 商家主动扣款 | 续费时由谁发起扣款，由 `deduct_type` 决定 |
| 产品类型 | 周期订阅 / 自动续购 / 单笔支付 | 使用哪套产品、协议和接口 |

服务商代开发描述调用方身份；普通周期订阅默认支付宝托管扣款。单凭服务商身份不能推断特殊扣款、关单等额外权限；用户明确提出其他模式或定向接口时，才查[专项条件](access-modes.md)。

## 三、职责边界

| 参与方 | 主要职责 |
|---|---|
| 商户 | 完成账号认证、产品开通和授权；确认商品、价格、权益、取消和退款规则；承担用户服务与业务运营责任 |
| 服务商 | 创建并维护第三方应用；安全保存应用密钥和商户授权令牌；代调用接口；处理通知；保障租户隔离、幂等、监控和故障补偿 |
| 支付宝 | 校验应用与商户授权；处理用户签约和支付；管理订阅生命周期；按产品规则扣款并发送状态通知 |

商户和服务商需要在项目开始前明确以下映射和同步责任：

- 商户、授权关系与服务商租户
- 商户用户与 `customer_id`
- 商户商品/套餐与 `product_id`、`price_id`
- 商户订单/权益与 `subscription_id`、支付单号、退款请求号
- 订阅状态、权益开始/结束时间和退款状态

## 四、接入前置条件

### 商户侧

- 已完成支付宝商家账号认证。
- 已确认订阅商品、价格、周期、试用、优惠、取消和退款规则。
- 已按当前准入流程开通对应订阅产品能力。
- 已安排具备权限的人员完成第三方应用授权。
- 已明确权益系统、客服和退款处理负责人。

### 服务商侧

- 已创建、配置并上线第三方应用。
- 已完成 RSA2 加签配置；涉及要求证书模式的资金操作时，按正式接口要求配置证书。
- 已配置消息服务、回调处理、主动查询补偿和监控告警。
- 已具备按商户安全保存授权关系、隔离数据和审计操作的能力。
- 已按正式接入资料完成支付/签约链接的服务端签名协作能力。

## 五、完整接入流程

```text
服务商创建并上线第三方应用
  -> 商户开通订阅产品
  -> 商户确认第三方应用授权
  -> 服务商保存该商户的 app_auth_token
  -> 代商户创建商品、循环价格和客户
  -> 代商户创建订阅并取得支付/签约入口
  -> 用户完成签约和支付
  -> 服务商接收支付宝通知
  -> 服务商同步商户权益系统
```

每个商户必须独立授权。服务商不得用商户甲的 `app_auth_token` 操作商户乙的商品、客户或订阅。产品开通申请、审核结果查询和开发准备入口见[商家产品开通与接入准备指南](../../onboarding/token-pay/guidance.md)。

## 六、代调用授权操作

代调用授权是所有新商户统一的开通前置步骤，不应因为该步骤自动进入服务商模式。PC 端、支付宝 APP、应用选择和产品权限的完整操作见[商家产品开通与接入准备指南](../../onboarding/token-pay/guidance.md#新商户代调用授权必需)。

明确采用服务商代开发时，还需在页面显示授权成功后，将授权结果关联到正确商户，核对第三方应用和产品范围，并安全保存该商户的 `app_auth_token`。每个需要代调用的第三方应用都必须获得独立授权。

## 七、接口调用规则

### 7.1 公共身份参数

| 参数 | 服务商模式下的含义 |
|---|---|
| `app_id` | 服务商第三方应用的 APPID |
| `app_auth_token` | 当前被代调用商户授予该应用的授权令牌 |
| `sign` | 使用服务商第三方应用私钥生成；证书模式同时使用对应证书配置 |
| `biz_content` | 与商家自研模式相同的业务参数 |

`app_auth_token` 是公共请求参数，不放入 `biz_content`。业务请求中不要自行添加正式接口文档未定义的模式、调用方或签名协作字段。

概念请求如下，所有值均为占位符：

```http
POST https://openapi.alipay.com/gateway.do?app_id=SERVICE_PROVIDER_APP_ID
  &method=alipay.trade.subscription.create
  &app_auth_token=MERCHANT_APP_AUTH_TOKEN
  &charset=UTF-8
  &sign_type=RSA2
  &timestamp=YYYY-MM-DD%20HH:mm:ss
  &version=1.0
  &sign=GENERATED_SIGNATURE
Content-Type: application/x-www-form-urlencoded

biz_content={"customer_id":"MERCHANT_CUSTOMER_ID","items":[{"price_id":"MERCHANT_PRICE_ID"}]}
```

### 7.2 资源归属与生命周期上下文

- 代调用创建的 `product_id`、`price_id`、`customer_id` 和 `subscription_id` 均归属被授权商户。
- 查询、修改、取消、扣款和退款必须继续使用同一商户的授权上下文。
- 同一订阅生命周期应持续使用创建该订阅时的第三方应用授权关系。需要更换服务商应用或迁移授权时，先通过正式接入渠道确认存量订阅处理方案。
- 跨商户使用资源 ID 或授权令牌会被权限校验拒绝。

## 八、支付与签约链接

与商家自研模式相比，服务商模式需要额外完成支付/签约链接的服务端签名协作：

1. 支付宝侧确定本次签约或支付的业务内容。
2. 服务商通过准入时配置的协作接口接收待签业务内容。
3. 服务商保持业务内容不变，按正式协议使用自己的第三方应用私钥和当前商户授权上下文生成完整响应。
4. 支付宝侧据此组装用户可访问的支付/签约入口；入口最终可用性以用户拉起时对应用、授权和业务参数的实际校验结果为准。

服务商必须遵守：

- 只处理正式接入资料允许的方法和场景。
- 不修改金额、订单号、签约参数或其他业务内容。
- 使用服务商第三方应用的 APPID 和对应应用私钥；证书模式同时配置匹配的证书信息。
- 使用当前商户的授权令牌，不使用全局默认令牌。
- 待签内容、授权令牌和应用私钥只在服务端处理。前端仅接收后端返回的最终不透明支付/签约链接，不解析或改写链接参数。
- 不记录授权令牌或完整签名内容；排障日志只保留脱敏的商户标识、请求号、方法和结果码。

具体协作接口名称、请求字段、响应结构和传输鉴权属于服务商准入后的技术契约，以正式下发资料为准，不从内部实现或旧方案反推。

## 九、支持的订阅能力

| 环节 | 接口/操作 | 服务商侧关注点 |
|---|---|---|
| 商品 | `alipay.trade.product.create/modify/query` | 使用当前商户授权上下文 |
| 价格 | `alipay.trade.price.create/query` | 周期订阅创建循环价格 |
| 客户 | `alipay.trade.customer.create` | 按商户隔离客户标识 |
| 创建 | `alipay.trade.subscription.create` | 普通订阅、免费试用和低价试用均可能返回支付/签约入口 |
| 查询 | `alipay.trade.subscription.query` | 用查询补偿通知并核对状态 |
| 升降级 | `UPGRADE` / `DOWNGRADE` | 升级立即支付，降级下周期生效 |
| 席位 | `INCREASE_QUANTITY` / `DECREASE_QUANTITY` | 扩容立即支付，缩容下周期生效 |
| 取消 | `CANCEL` | 支持周期末取消和立即取消 |
| 恢复 | `REVERT_CANCEL` | 需要用户重新确认时可能返回签约入口 |
| 预计退款 | `alipay.trade.subscription.estimatedrefund.query` | 取消前展示预计可退金额 |
| 裸退款 | `alipay.trade.refund` | 只退款，不自动取消订阅 |

是否触发支付/签约签名协作，以具体业务场景和接口实际返回为准。服务商不要把“每次调用必定触发协作”写成固定假设。

## 十、通知与退款

服务商模式下，订阅相关通知投递至创建该订阅时使用的第三方应用。服务商负责映射回具体商户，并同步权益系统。

| 通知 | 处理要求 |
|---|---|
| `alipay.trade.subscription.changed` | 处理生效、试用、续费、升级、降级、取消和恢复等状态变化 |
| `alipay.trade.commercial.batchrefund.changed` | 确认取消退款、独立退款和客诉超标自动退款的最终结果 |

立即取消并退款时必须分别处理两类结果：

1. `alipay.trade.subscription.changed` 的 `cancel` 表示订阅已取消。
2. `alipay.trade.commercial.batchrefund.changed` 的 `SUCCESS`、`PARTIAL_SUCCESS` 或 `FAILED` 表示退款终态。

取消请求的同步成功仅确认订阅取消。用取消响应的 `refund_order_id` 关联批量退款通知或查询的 `request_no`，按批次状态和明细更新退款记录。

独立退款用发起响应中的 `refund_order_id` 关联通知的 `request_no`。客诉超标自动退款用 `refund_scene=AUTO_PENALTY` 识别，`refund_reason` 包含投诉工单号。主动核对退款结果时，可按 `request_no` 查询批次。[退款通知处理](notification-guide.md)

通知处理统一要求：

- 使用支付宝公钥或证书验签。
- 按通知业务主键做幂等，允许重复投递。
- 可靠保存原始业务结果后再驱动权益变化。
- 成功受理后精确返回 `HTTP 200` 和文本 `success`。
- 对关键状态配置主动查询补偿，不能只依赖单次通知。

## 十一、安全要求

- 商户不得向服务商提供商户应用私钥。
- 服务商应加密保存 `app_auth_token`，限制读取权限，并在日志、监控、工单和告警中脱敏。
- 每次调用先确定商户租户，再读取该商户的授权令牌；禁止使用全局默认 token。
- 服务商私钥、证书、授权令牌和签名协作原文不得进入浏览器、移动应用包或前端代码。最终支付/签约链接可按业务需要返回前端，但不得解析、改写、长期持久化或写入日志。
- 商户撤销授权后，服务商应停止新的代调用并提示重新授权；撤销授权不等于取消存量订阅。
- 涉及退款、权益和通知重放的操作应记录脱敏的操作人、商户、请求号、订阅号和结果。

## 十二、联调验收

### 授权与隔离

- [ ] 商户能识别服务商名称和授权范围并完成授权。
- [ ] 服务商能把授权结果正确关联到对应商户。
- [ ] 两个测试商户的 token、商品、客户和订阅不能交叉访问。
- [ ] 授权失效或撤销后，新调用被阻止并产生可处理的告警。

### 订阅生命周期

- [ ] 普通订阅、免费试用和低价试用可正常拉起支付/签约页。
- [ ] 首次支付、续费、升级、降级、扩容、缩容和恢复结果正确。
- [ ] 周期末取消和立即取消的权益截止时间正确。
- [ ] 立即取消与退款结果分别确认，失败和部分成功可处理。

### 通知与安全

- [ ] 订阅和退款通知均投递到预期第三方应用。
- [ ] 重复通知不会重复开通、延长、关闭权益或退款。
- [ ] 通知丢失时可通过查询任务补偿。
- [ ] 日志和错误响应不包含 token、私钥、证书或完整签名内容。

## 十三、常见问题

### 服务商代开发后，订阅和交易属于谁？

属于被授权商户。服务商是技术调用方，不因代调用成为商品、客户、订阅或资金的归属方。

### 商户需要把私钥交给服务商吗？

不需要。服务商使用自己的第三方应用和密钥，商户通过开放平台完成授权。

### 一个服务商可以服务多个商户吗？

可以。每个商户必须独立授权，服务商按商户分别保存授权令牌和业务资源，不能混用。

### 服务商模式等于商家主动扣款吗？

不等于。服务商模式决定谁完成技术调用；`deduct_type` 决定谁发起周期扣款。

### 商户撤销授权后，已有订阅会自动取消吗？

不能这样假设。撤销授权会影响后续代调用，存量订阅仍需按实际状态和正式迁移方案分别查询、取消或处理。

### 通知由谁接收？

订阅相关通知发送给创建该订阅时使用的第三方应用。服务商处理后再同步给具体商户。

### 退款后订阅会自动取消吗？

取决于接口。`CANCEL + cancel_at_period_end=false` 的立即取消流程可异步发起退款；周期末取消不表示自动退款。`alipay.trade.refund` 只是裸退款，不会自动取消订阅。
