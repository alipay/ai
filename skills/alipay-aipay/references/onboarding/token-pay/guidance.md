# AI连续订阅（Token Pay）· 周期订阅的商家办理与上线条件

执行任务沿用[全局阶段记录](../../normal/telemetry.md)和[会话授权](../../normal/conversation-telemetry.md)，产品标识为 `token-subscription`。实际交付相应办理指引才记 `token.guidance_delivered`；它不代表商家已申请、公海已收到线索、签约已通过或产品已开通。只问问题时不建业务 run；仅使用服务仍记录执行阶段，不采集 query 或其摘要。

本页用于**周期订阅**的商家办理及上线准备。想了解产品范围、经营规则或结算时，直接看[AI连续订阅产品概览](../../integration/token-pay/product-overview.md)。自动续购、商业订单、企业支付、发票和企业认证的准入、调用身份和回执不同，分别看[自动续购](auto-renewal.md)、[商业订单](single-payment.md)、[B2B](b2b.md)、[发票](invoice.md)、[企业认证](verification.md)。

先按当前身份和应用核实[订阅官方办理说明](https://aipay.alipay.com/docs/subscribe/introduce.md)。已有企业身份（含选择该企业的操作员）可按页面指引办理；个人身份或需要注册新企业时查看[联系销售](https://aipay.alipay.com/merchant-intent)。资格、材料要求和处理状态以当期页面及控制台为准。

本入口提供商家准备、办理链接及结果核对。本包尚未提供经确认的订阅线索自动投递、签约提交或状态查询工具。按已取得的证据分别表述“已提供办理入口”“线索已接收”“申请已提交”“已生效”。不调用网页收款、移动应用收款或 402 的签约脚本。终端会员首购授权属于[开发与联调](../../integration/token-pay/flow.md)。

## 办理顺序、计费和结算

1. 开始申请前，在[官方产品介绍](https://aipay.alipay.com/docs/subscribe/introduce.md)核对经营主体、经营类目、所售商品及申请条件；类目编码与材料见[商家经营类目](https://opendocs.alipay.com/common/02khjv.md)。官方介绍列出的经营类目为 B0121 软件开发、B0120 互联网数据服务、B0113 信息检索/网络论坛、B0125 其他在线应用或综合服务、B0112 在线工具、B0164 话费充值与缴费；正式受理以当期页面为准。运营与结算要求见[官方产品介绍的产品运营规则说明](https://aipay.alipay.com/docs/subscribe/introduce.md)。不符合条件的商家可使用该页的[意向登记](https://render.alipay.com/p/yuyan/180022670000100564/index.html)。提交意向、销售受理、申请审核和最终生效是不同结果。
2. 按该商家实际开通的基础产品逐笔计费，商家扣款、APP 支付、电脑网站支付各自的费率在[签约管理](https://b.alipay.com/page/products-sign/dynlink/productSign/signManage.htm)核对。默认收款账户、止付及结算安排以商家协议和开通通知为准；官方接入说明列出默认收款到签约账号余额，商家扣款订单在约定管控期内止付，具体账期以站内信或邮件为准且可能随经营情况调整，不可据此承诺固定 T+N。
3. 开通并核对实际调用应用所需的代调用授权后，按[接入准备](https://opendocs.alipay.com/solution/repo-046zj4?ref=api)配置应用、加签、网关与通知。代码和本地模拟可提前；完成这些操作不代表生产交易或用户扣款协议已生效。

## 新商户代调用授权（必需）

新商户开始正式周期订阅接入前，为实际调用接口的应用完成代调用授权。准备工程或使用独立订阅沙箱时可以先行，转生产再核对本节。优先引导商户使用 PC 端操作；手机端使用支付宝 APP 扫码作为备选。授权入口应取自当前正式接入资料，不要在 Skill、业务代码或长期文档中固化授权链接里的应用标识、回调地址或业务参数，也不要复用非公开图片地址。

### 发送授权入口

| 商户操作端 | 发送内容 | 商户登录身份 |
|---|---|---|
| PC 端（推荐） | 当前有效的授权链接 | 使用收单商户号对应账号登录支付宝商家平台（B 站） |
| 手机端 | 当前有效的授权二维码图片 | 使用 PID 对应的支付宝账号登录支付宝 APP |

### 选择应用和产品权限

- 选择实际调用接口时使用的应用；如果多个应用都会调用支付宝接口，每个应用都需分别完成授权。
- 接口调用权限必须包含“商家扣款产品”。这是授权产品范围，不代表需要向商户介绍其他周期扣款模式。
- 商户有 APP 支付场景时，建议同时授权“APP 支付”，并选择移动应用。
- 商户有网页支付场景时，建议同时授权“电脑网站支付”，并选择网页应用。
- 某个应用下缺少 APP 支付或电脑网站支付时，先核对应用类型；网页应用和移动应用可能需要分别授权。
- 全权委托开发授权由商户自主决定。选择后，新增支付产品时可能无需重复授权；不选择时，按当前所需应用和产品做最小范围授权，后续新增范围时重新授权。

### PC 端确认授权

1. 商户登录支付宝商家平台（B 站）。
2. 在浏览器中打开收到的当前有效授权链接。
3. 在“授权的商家信息”中选择实际调用接口的应用。
4. 核对接口调用权限、支付产品和应用类型。
5. 确认授权并完成短信验证码验证；验证成功即完成授权。

### 手机端确认授权

1. 商户使用 PID 对应的支付宝账号登录支付宝 APP。
2. 使用支付宝 APP 扫描收到的当前有效授权二维码。
3. 选择实际调用接口的应用；多个调用应用分别授权。
4. 核对接口调用权限、支付产品和应用类型。
5. 若页面再次展示全权委托授权引导，由商户自主选择同意或拒绝。
6. 页面显示授权成功后，核对授权商户、正式调用应用和已授产品范围，将结果用于正式接入。

## 一、创建应用

### 操作步骤

1. 登录 [支付宝开放平台控制台](https://open.alipay.com/)
2. 创建应用类型：
   - 小程序
   - 移动应用
   - 网页应用

### 获取 APPID

创建成功后，系统生成唯一的 **APPID**，用于后续所有接口调用。

## 二、配置应用

进入「开发 > 开发设置」进行配置。

### 2.1 接口加签方式（必填）

**用途**：防止数据篡改，保障应用和支付宝交互的安全性。

**类型选择**：
- **公钥模式**：适用于一般接口
- **证书模式**：本订阅接入手册要求裸退款 `alipay.trade.refund` 使用证书模式。按[设置证书加签方式](https://opendocs.alipay.com/common/056zub.md)配置应用公钥证书、支付宝公钥证书与根证书，再按[Java 证书模式示例](../../integration/token-pay/code-example-java.md#证书模式)初始化客户端并使用 `certificateExecute`。其他资金接口分别核对该接口及应用的要求。

**普通公钥模式的配置步骤**：
1. 本地生成 RSA2 密钥对（推荐 2048 位）
2. 在控制台上传商户公钥
3. 获取支付宝公钥（用于验签）

### 2.2 服务器 IP 白名单（选填）

**用途**：提高应用访问开放平台的安全性，避免私钥泄漏导致业务受损。

**配置建议**：
- 仅添加服务器出口 IP
- 多个 IP 用逗号分隔

### 2.3 应用网关（必填）

**用途**：接收支付宝异步通知消息。

**要求**：
- 必须是 http(s) 公网可访问地址
- 支持接收 POST 请求
- 必须返回 `HTTP 200 + "success"` 表示处理成功

**示例**：`https://your-domain.com/alipay/notify`

### 2.4 接口内容加密方式（选填）

**用途**：加/解密 OpenAPI bizContent 报文内容，提升传输安全性。

**支持算法**：AES

### 2.5 服务器域名白名单（选填）

**适用场景**：小程序需要获取客户端域外资源时配置。

### 2.6 H5 域名（选填）

**适用场景**：小程序使用 web-view H5 页面承载组件时，需配置所有域名地址（含静态资源）。

### 2.7 授权回调地址（选填）

**适用场景**：网页/移动应用的用户信息授权。

**要求**：授权链接中的 `redirect_uri` 必须与此回调地址一致。

### 2.8 订阅消息服务（选填）

**用途**：异步消息通知，提高 API 调用效率。

**类型**：
- **主动推送服务（From 蚂蚁）**：接收支付宝推送的消息
- **消息回流服务（To 蚂蚁）**：向支付宝发送消息

## 三、上线应用

### 小程序

- 审核通过后**自动上线**

### 网页/移动应用

- 需要**手动上线**
- 提交审核后，以控制台显示的审核进度和结果为准
- 审核通过后应用状态变为「已上线」

## 四、绑定商家账号（可选）

**用途**：使用支付和资金相关产品时，需将应用与支付宝商家平台账号绑定。

**操作路径**：开放平台控制台 > 应用详情 > 绑定商家账号

## 五、开通产品

**开通步骤**：
1. 按产品页面要求填写并提交开通申请。
2. 等待系统审核，不承诺固定审核时长。
3. 通过审核短信或[产品开通情况](https://b.alipay.com/page/products-sign/dynlink/productSign/signManage.htm)页面确认结果。
4. 核对控制台中已开通的产品和接口权限，再由商家按正式流程推进生产验收；本 Skill 只核对已有脱敏证据。

周期订阅创建和修改需要商家应用至少具备 APP 支付或[电脑网站支付](https://b.alipay.com/page/product-workspace/product-detail/I1080300001000041203/newProductList?)中的一种产品权限：移动端通常开通 APP 支付，PC 浏览器场景开通电脑网站支付；两者均未开通时不能生成支付/签约链接。正式接入所需授权见[新商户代调用授权](#新商户代调用授权必需)。

电脑网站支付并签约链接同时承载付款和周期订阅签约。浏览器跳回商家页面只表示用户完成页面操作，不能单独作为支付或签约成功依据；商家必须校验 `alipay.trade.subscription.changed` 通知并通过订阅查询确认终态后再开通权益。

## 商家上线前复核



已申请并拿到正式应用及配套密钥的商户可直接核对已有脱敏生产证据并做上线准备，不要求先通过沙箱；本 Skill 不在生产网关运行验证；尚未拿到正式密钥时主动推荐先做沙箱验证，尊重商户已有的明确环境选择。持有正式密钥不代表以下权限、授权、通知或交易门禁已通过。

商户选择周期订阅沙箱接入时，按[沙箱接入指南](../../integration/token-pay/sandbox/sandbox-integration.md)检查沙箱应用、凭据、接口和模拟闭环，不用生产开通或经营门禁阻止其开始测试。以下用于正式上线的门禁应单独记录；沙箱验证不能将生产权限、真实扣款或生产通知标为 `VERIFIED`。

沙箱工程交付的执行状态、恢复记录和验收范围按[沙箱自动接入交付](../../integration/token-pay/sandbox/sandbox-delivery.md)维护；不要为了填写下方生产门禁而暂停沙箱实现。沙箱通过也不回填生产门禁。

- 准备度用于推进接入和判断下一步，不用于给普通问答增加检查流程。
- 不使用缺乏证据基础的百分比。按门禁状态说明商家能否继续，以及还缺什么。
- 只更新本次取得新证据的项目；未知不等于失败，用户口述完成也不等于已验证。
- 优先处理最靠前的阻塞门禁。后续项目可以并行准备，但不能用后续成功掩盖前置阻塞。
- 用户已有证据时直接复用，不要求从头重复整个 onboarding。

## 状态与证据

### 门禁状态

| 状态 | 含义 |
|---|---|
| `UNKNOWN` | 尚未获得足够信息，不能判断 |
| `ACTION_REQUIRED` | 已确认需要商家或实施方完成具体动作 |
| `READY_UNVERIFIED` | 商家表示已完成，或只看到静态配置，但尚无足够验证结果 |
| `VERIFIED` | 已有与该门禁相匹配的可靠证据 |
| `BLOCKED` | 已确认存在阻塞，且当前无法在授权范围内继续 |

### 常见证据等级

| 证据 | 可支持的判断 |
|---|---|
| 商家口述或计划 | 记录上下文，最多支持 `READY_UNVERIFIED` |
| 控制台状态、审核或授权结果 | 验证相应平台准备项 |
| 脱敏配置检查、连通性和验签测试 | 验证相应技术准备项 |
| 真实语言构建和自动化测试结果 | 验证工程实现，但不能证明平台权限或真实交易成功 |
| 可关联的 API 响应、通知、查询和商户业务状态 | 验证联调闭环及对应业务结果 |

## 准备度门禁

### 1. 产品与经营适配

- 商家目标属于固定周期售卖会员、套餐或席位，而不是余额阈值自动续购或一次性交易。
- 企业账号、经营类目、产品准入、费率和结算预期不存在已知阻塞。
- 按[商户默认管控规则](../../integration/token-pay/merchant-default-controls.md)核对计划的商品价格、扣款周期和首期优惠；默认商品价格最高 500 元，周期为 7 天至 3 个月／93 天。
- 用户明确了解周期扣款和用户取消的基本经营责任。

### 2. 产品与应用开通

- 周期订阅产品已经申请并以控制台实际结果确认开通。
- 实际调用应用已经创建并处于目标环境允许调用的状态。
- 根据用户支付场景，至少具备 APP 支付或电脑网站支付中的一种必要能力。
- 零元、试用等受限场景只有在实际使用时才检查对应业务准入；默认黄金路径不主动展开。

### 3. 调用身份与授权

- 已明确实际调用使用的应用和商户上下文。
- 新商户已完成当前正式接入资料要求的代调用授权，应用和产品范围与实际调用一致。
- 后续商品、价格、客户和订阅操作保持相同应用与商户上下文。

### 4. 安全配置与回调

- RSA2 密钥或证书按目标接口要求配置，私钥通过安全方式注入。
- 生产上线验收使用生产网关及生产凭据，字符集、签名方式和 SDK 客户端配置一致；沙箱配置与证据单独记录。
- 应用网关公网可访问，能够接收原始通知参数、验签并精确返回 `HTTP 200` 和文本 `success`。
- 没有在代码、日志或对话中暴露真实私钥、完整证书或用户敏感信息。

### 5. 工程最小闭环

- 实现商品、价格、客户和订阅创建所需的最小调用链，并持久化后续操作所需资源 ID。
- 实现通知验签、业务幂等、主动查询补偿和权益处理。
- 对 SDK 异常、业务失败、超时和未知结果采用不同处理方式。
- 相关代码通过真实语言构建和必要自动化测试。

### 6. 联调闭环

- 使用受控测试客户和明确的测试金额、退款与数据处置方案。
- 创建结果、支付签约、异步通知、主动查询和商户权益状态能够用同一业务链路关联。
- 页面跳转和同步响应未被误当作最终支付或签约结果。
- 重复通知、查询补偿和至少一个失败路径已经验证。

### 7. 生产可靠性与经营准备

- 已配置必要的业务监控、告警、对账或状态补偿机制。
- 已明确发布、回滚、异常升级和用户服务责任人。
- 已配置交易投诉监控、处理责任人和处置闭环。
- 已为处理人员配置所需客服权限。
- 已建立首次投诉 72 小时、升级投诉 24 小时内处理并反馈工单的闭环机制。

> ⚠️ **商家支付交易风险投诉处理**
>
> 商家上线收款前须建立投诉监控、处理责任人和处置闭环。首次投诉须在 **72 小时**内、升级投诉须在 **24 小时**内妥善处理，并在处理后完成工单反馈；超时或未完结会影响服务质量评价，投诉风险持续偏高可能触发风险交易拦截、账户限权等措施。请阅读[《商家支付交易风险投诉处理指南&说明》](https://opendocs.alipay.com/b/05f8ww)，具体以最新官方规则为准。

不要在接入回答中展开整篇投诉规则；只有用户继续询问操作细节时，再说明商家平台入口、客服权限、退款反馈和工单完结要求。

## 更新与输出

接入推进过程中，按门禁输出当前状态和证据，不要求机械展示全部项目。优先说明：

1. 当前所在阶段和最靠前的未完成门禁。
2. 本次新增的验证证据。
3. 当前阻塞或商家必须完成的动作。
4. 下一验收点及其需要的证据。

只有所有上线阻塞门禁均为 `VERIFIED`，且遗留风险已经明确处理时，才可以给出“具备上线条件”的判断。`READY_UNVERIFIED`、代码生成完成或页面跳转成功都不能代替上线验证。
